# 🌱 إنجازات أطفالي
موقع عربي RTL لمتابعة عادات الأطفال ودراستهم، بتصميم متجاوب ودون مقارنة بين الإخوة.

## ما يعمل
- ملفات الأطفال بأسماء مستعارة وصور رمزية وأهداف أسبوعية.
- معايير قابلة للتخصيص، وثلاثة مستويات بنقاط يحددها ولي الأمر.
- سجل واحد لكل طفل ومعيار وتاريخ، مع تعديل التقييم والملاحظة.
- مكتسبات ونقاط متاحة منفصلة؛ المكافآت تخصم الرصيد المتاح فقط.
- اختبارات اختيار متعدد يكتبها ولي الأمر، وتصحيح آلي، ومحاولة محسوبة يوميًا لكل اختبار وطفل.
- تقارير يومية وأسبوعية وشهرية ومخصصة، وطباعة عربية.
- تصدير واستيراد JSON مع التحقق والتأكيد.
- مزامنة عبر Supabase، وتسجيل دخول حقيقي، وعزل بيانات كل حساب بسياسات RLS.
- رفض التعديل المتعارض بين الأجهزة بدل الكتابة فوق بيانات جهاز آخر.

## الحفظ المحلي مقابل المزامنة
الحفظ المحلي يخص متصفحًا وجهازًا واحدًا وقد يضيع بمسح بيانات المتصفح. هذه النسخة تستخدم قاعدة بيانات Supabase المشتركة للحفظ الفعلي؛ لا تحفظ بيانات الأطفال في localStorage. يُحفظ رابط المشروع ومفتاحه العام محليًا، ورمز جلسة الدخول في sessionStorage حتى إغلاق علامة التبويب. وضع التجربة يعمل في الذاكرة فقط ولا يتزامن ولا يدوم بعد تحديث الصفحة.

## ١. إعداد قاعدة البيانات (مطلوب للحفظ من عدة أجهزة)
1. أنشئ مشروعًا في https://supabase.com/dashboard .
2. افتح SQL Editor والصق محتوى [schema.sql](schema.sql) وشغّله.
3. من Authentication → Users أنشئ حساب ولي الأمر ببريدك وكلمة مرور قوية، واختر تأكيد البريد عند الإنشاء الإداري. استخدم الحساب نفسه على أجهزتك.
4. عطّل التسجيل العام من إعدادات Authentication إن كان الموقع خاصًا بالعائلة. لا حاجة لتفعيل anonymous sign-ins.
5. انسخ Project URL ومفتاح **Publishable** (أو anon القديم) من إعدادات المشروع. لا تستخدم `service_role` أو `sb_secret_` في الواجهة أو المستودع.
6. افتح الموقع وأدخل الرابط والمفتاح العام، ثم سجّل الدخول بحساب ولي الأمر.
7. أضف ملفات الأطفال من داخل التطبيق بعد الدخول. لم تُضمّن أسماء أو أعمار حقيقية في الكود العام.
8. على جهازك الثاني أدخل إعدادات المشروع نفسها وسجّل الدخول بالحساب نفسه. اضغط «مزامنة الآن» في الإعدادات لجلب التعديلات الجديدة.

مرجع الحماية: https://supabase.com/docs/guides/database/postgres/row-level-security
المفتاح العام ليس كلمة مرور؛ الحماية تأتي من تسجيل الدخول وسياسة `auth.uid() = owner_id`. جميع الكتابات تمر بدالة ذات فحص هوية وإصدار وقيم أساسية، ولا يملك الزائر غير المسجل أي صلاحية على السجلات.

## ٢. تشغيل محلي
تحتاج Python 3، ولا توجد حزم واجهة مطلوبة:
```sh
python3 -m http.server 8080
```
افتح http://localhost:8080 . اختر التجربة المؤقتة لمعاينة الموقع، أو اربط قاعدة البيانات للحفظ. لا تفتح index.html مباشرة بصيغة file:// لأن المشروع يستخدم JavaScript modules.

## ٣. النشر على GitHub Pages
1. من مستودع `ashtayyat/kids` افتح Settings → Pages.
2. اختر **GitHub Actions** مصدرًا للنشر.
3. من Actions شغّل **Publish Arabic family website** عبر Run workflow إن لم يبدأ تلقائيًا.
4. بعد نجاحه يظهر الرابط في قسم Deployments، ويكون عادة: https://ashtayyat.github.io/kids/ . لا يعتبر الرابط منشورًا قبل نجاح عملية النشر.

يُرفع إلى Pages فقط index.html وapp.js وcore.mjs وstyle.css. الكود عام، لكن بيانات حسابك تبقى في قاعدة البيانات ولا تُرفع معه. لا ترفع ملفات النسخ الاحتياطية إلى GitHub.

## ٤. الاستخدام
- أضف الطفل وهدفه الأسبوعي من «أطفالي».
- خصّص المعايير والنقاط من «الإعدادات».
- اختر الطفل والتاريخ في التقييم اليومي. «لم يُقيّم بعد» تزيل التقييم المحفوظ لهذا اليوم عند الحفظ.
- يبدأ الأسبوع يوم الأحد بحسب تاريخ جهاز المستخدم. استخدم المنطقة الزمنية الصحيحة على جميع أجهزة الأسرة.
- النجوم هي النقاط المكتسبة، والرصيد هو المكتسب ناقص المكافآت المستبدلة.
- لا يمكن خفض النقاط تحت الرصيد الذي صُرف؛ يظهر تنبيه عند ذلك.
- الاختبار: اكتب كل سؤال في سطر بصيغة `السؤال | الأول | الثاني | الثالث | 1`. رقم الإجابة 1 أو 2 أو 3. النقاط متناسبة مع الإجابات الصحيحة وتُقرّب إلى أقرب عدد صحيح.
- اطبع التقارير من صفحة التقارير. لا توجد أعمدة ترتيب أو مقارنة بين الأطفال.

## ٥. الاختبارات والتحقق
```sh
node --test tests/*.test.mjs
node --check app.js
```
الاختبارات تغطي تحديث التقييم دون تكرار، تصفية التاريخ، استبدال النقاط وعدم تجاوز الرصيد، منع خفض النقاط المصروفة، تصحيح الاختبار ومنع المحاولة المكررة، واستعادة النسخ الاحتياطية.

بعد إعداد Supabase اختبر يدويًا:
1. حفظ تقييم على جهاز وظهوره عند المزامنة على جهاز آخر.
2. تعديل نفس البيانات من جهازين: يجب رفض النسخة القديمة برسالة تعارض، ثم المزامنة وإعادة التعديل.
3. تسجيل الخروج ثم التأكد أن طلب البيانات بدون جلسة لا يعيد بيانات.
4. حساب آخر لا يستطيع الوصول إلى صفوف العائلة الأولى.
5. إضافة طفل ومعيار واختبار ومكافأة ثم تجربة الطباعة على شاشة هاتف.

## حدود النسخة الحالية
- إعداد Supabase وتفعيل Pages يحتاجان إلى حسابك؛ لا يوجد مشروع قاعدة بيانات مضمن أو كلمات مرور افتراضية.
- جميع الأجهزة تستخدم حساب ولي الأمر نفسه. صفحة الطفل عرض مريح داخل جلسة ولي الأمر، وليست حسابًا محدود الصلاحيات للطفل. لا تسلّم الجلسة للطفل دون إشراف إذا أردت منع التعديل.
- لا توجد مزامنة حية تلقائية؛ الجلب عند فتح الموقع والضغط على المزامنة، والحفظ بعد كل تعديل. لا يوجد حفظ دون اتصال.
- الاختبارات تدريبية؛ الحلول متاحة للمتصفح وليست صالحة لامتحان رسمي مؤمّن.
- لا توجد مهام مختلفة حسب الطفل حتى الآن؛ المعايير مشتركة والاختبارات يختارها ولي الأمر وفق العمر.
- لا يوجد حذف ملفات الأطفال أو سجل المكافآت، ولا استرجاع كلمة مرور من داخل الواجهة؛ إدارة الحساب من Supabase.
- النسخة الاحتياطية JSON غير مشفرة. الاستيراد يستبدل كامل الحساب بعد التأكيد. الحجم الأقصى ٢ ميغابايت.
- حفظ الحساب كاملًا كوحدة واحدة مناسب لعائلة صغيرة؛ لا يستهدف مؤسسة أو آلاف المستخدمين ضمن حساب واحد.
- اختبارات الحسابات آلية؛ الاختبار السحابي واختبار الصلاحيات يحتاجان مشروع Supabase فعليًا.
